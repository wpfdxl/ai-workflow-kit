# 开发方案 Review

> 人 review `01_开发方案.md`。任一不过 → 改方案 → 再过。全过才进阶段③。

## A. 范围与分层
- [ ] 仓库 / 服务 / 端盘点完整
- [ ] 分层符合 `project.local.md` 与目标仓惯例（入口不直连存储）
- [ ] 跨模块走对方业务层
- [ ] 配置 / 常量不夹带业务方法（若本仓有这条禁令）

## B. 存储设计
- [ ] 命名符合本仓迁移规范，避开保留字
- [ ] 主键、时间戳、软删等必备字段按本仓约定
- [ ] 索引够用、命名清楚
- [ ] 跨库 / 跨服务有日志与补偿

## C. 接口清单
- [ ] 每个对外接口有方法 / 路径或名称 / 鉴权 / 端
- [ ] 命名符合本仓对外约定
- [ ] 多端路径分别列出（如有）
- [ ] 无对外 API 已标明，并写清真实调用方式

## D. 核心流程
- [ ] 覆盖关键分支、异常、边界
- [ ] 空态 / 无数据有说明
- [ ] 排序、过滤明确

## E. 缓存（有则过；无则勾「无」）
- [ ] 无缓存，或 key / 过期 / 失效写清
- [ ] 并发刷新只用于公共热点，不用于纯个人数据（若适用）
- [ ] 数据结构选择合理

## F. 风险与兼容
- [ ] 向下兼容
- [ ] 灰度 / 开关 / 回滚
- [ ] 数据迁移（如有）

## G. 任务拆解
- [ ] 顺序合理（默认存储 → 业务 → 入口）
- [ ] 每个 Task 可独立执行、可独立验证
- [ ] 粒度合理

## H. 待确认
- [ ] 第 10 节 ❓ 已确认或明确仍阻塞（阻塞则不得进③④）
