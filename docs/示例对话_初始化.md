# 示例对话：Clone 后初始化工作流

下面是一段**可照抄**的对话流程。假设你已经把本仓库放到业务工程旁（或子目录）。

---

## 你（终端）

```bash
git clone <ai-workflow-kit-url> ai-workflow-kit
cd ai-workflow-kit
# 用 Cursor / 其它 AI IDE 打开「本目录」
```

可选：若 kit 在业务仓内：

```text
my-service/
  app/                 # 业务代码
  ai-workflow-kit/     # 本仓库
```

则 `code_root` 可填 `../` 或 `../app`（按实际）。

---

## 你 → AI（第一条消息）

1. 打开并粘贴：[`bootstrap/init_接入我的项目.md`](../bootstrap/init_接入我的项目.md) 里「给 AI 的整段」
2. 填好文末「我的项目信息」，例如：

```text
业务仓路径（code_root）：../
语言与版本：Go 1.25
框架与版本：Kratos
分层/架构：DDD（api / service / biz / data）
目录习惯：cmd/、api/、internal/...
API 风格：gRPC + HTTP；错误用 Kratos errors
DB / 缓存约定：MySQL 在 data 层；Redis 可选
禁止项 / 代码风格：biz 不 import data 实现；gofmt
是否写入 Cursor rules：是
是否保留开箱示例：否
其它约束：跨服务禁止 import 对方 internal
```

---

## AI 应做的事（你验收）

- [ ] 新建 `profiles/<你的id>/RULES.md` 等三文件
- [ ] `PROJECT.md` 已指向该 profile 与 `code_root`
- [ ] 已删除所有 `profiles/*-sample/`
- [ ] 已删除 `workspace/_example_*` 与对应 `doc/` 示例目录
- [ ] `INDEX.md` 表格已清空
- [ ] （可选）`.cursor/rules/<id>.mdc` 已生成
- [ ] 回复里列出了删除清单与「如何开第一个需求」

对照清单：[`哪些可以删.md`](哪些可以删.md)。

---

## 你 → AI（第二条：开第一个需求）

```text
按当前 PROJECT.md 的规范，新建需求「订单导出」：
1. 创建 workspace/订单导出/，用 _templates 生成 00~03 空文件，STATUS.md 标明阶段①
2. 根据下面需求描述填写 00_需求.md
3. 在 INDEX.md 登记一行
（需求描述：……）
```

然后继续用 `_prompts/step1_生成开发方案.md` 往下走即可。

---

## 常见问题

**Q：业务仓和 kit 是不是同一个 git？**  
随便。可以 submodule / 子目录 / 旁挂。只要 `code_root` 指对，编码阶段改的是业务仓文件。

**Q：初始化能不能只生成规范、先不删示例？**  
可以。项目信息里写 `是否保留开箱示例：是`。学完再手动删，或再跑一次 init 并改为否。

**Q：只想换规范、示例早就删了？**  
改用 [`bootstrap/step0_生成项目规范.md`](../bootstrap/step0_生成项目规范.md) 即可，不必走 init。
