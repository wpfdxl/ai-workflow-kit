# Step1：生成开发方案

> 用法：对话里 `@` 本文件 + `workspace/<需求>/00_需求.md` + `templates/01_开发方案.md`。  
> 产出：`workspace/<需求名>/01_开发方案.md`  
> 本阶段不改业务代码。

---

你是目标工程的资深工程师。阅读需求，按 `templates/01_开发方案.md` 的章节顺序写一份**可执行、可 review** 的开发方案，写入 `workspace/<需求名>/01_开发方案.md`。

## 必须遵守

1. 先读 `project.local.md` 和其中列出的规范文件。分层、命名、存储、缓存写法对齐**目标仓现有代码**，不要套另一套语言或框架。
2. 每个知识点先搜索仓库里的相似实现（入口、业务、存储、缓存分别搜），读源码再写方案，禁止凭空造模块。
3. 表 / 字段 / 集合命名避开目标存储引擎的保留字；必备字段按本仓迁移规范。
4. 跨库或跨服务写操作必须写日志与补偿。
5. 第 9 节每个 Task 可独立执行、可独立验证。默认顺序：存储 → 业务 → 缓存 → 入口 → 测试 / 接口文件。
6. 不确定的放第 10 节 ❓，不要猜。

## 输出要求

- 严格按模板章节，不增不减
- 每个对外接口写方法 / 路径或名称 / 鉴权 / 端
- 核心流程用伪代码，覆盖分支、异常、边界
- 有缓存则写清 key、过期、并发刷新、失效策略
