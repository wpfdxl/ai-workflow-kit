# Step2：生成接口文档

> 用法：`01` 已人 review 定稿。`@` 本文件 + 定稿 `01` + `templates/02_接口文档.md`。  
> 产出：`workspace/<需求名>/02_接口文档.md`；有对外 API 时再写 `docs/<需求名>/`。  
> 本阶段不改业务代码。

---

开发方案已定稿。基于它生成接口文档。

## 任务

1. 按 `templates/02_接口文档.md` 写 `02_接口文档.md`。
2. 若有对外 API：按 `project.local.md` 的格式写到 `docs/<需求名>/`（OpenAPI、Proto、Markdown、内部 JSON 等）。无对外 API 则在 `02` 标明「无独立接口」。

## 必须遵守

1. 每个接口包含：请求（多端路径分别列出）、参数表、业务规则、返回字段表、返回示例（正常 / 空态 / 错误）。
2. 类型写清（int / string / array / object 或本工程类型系统）；枚举列全。
3. 空态、无数据、边界必须有示例。
4. 排序、过滤、展示规则写进业务规则；文案由谁生成写清楚。
5. 路径 / 方法名跟目标仓对外约定一致（见 `project.local.md`）。
6. 只详写业务字段；顶层包装跟现有接口一致。
7. 每个返回字段（含嵌套）都有说明，不能空。

## 输出要求

- md：给人 review 和阶段④编码用
- `docs/` 文件：与 md 字段一致，格式只跟本工程既有约定
