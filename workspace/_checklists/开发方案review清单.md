# 开发方案 review 清单

> 人肉过。任一项不通过 → 改方案 → 再过。通过后才能 step2。

## A. 完整性

- [ ] 需求理解与 `00_需求` 一致，无漏功能点
- [ ] 影响范围（仓/模块/分层）列全
- [ ] 接口清单方法/路径/鉴权/端齐全
- [ ] 核心流程覆盖主路径 + 异常 + 边界
- [ ] Task 拆解可独立执行、顺序符合 profile `coding_order.md`

## B. 与规范一致

- [ ] 分层命名与依赖符合 active profile `RULES.md`
- [ ] 存储/API/缓存约定未与 profile 冲突
- [ ] 未误用其他 sample 栈的概念硬套

## C. 风险

- [ ] 兼容、回滚、迁移有说明（若涉及）
- [ ] ❓ 待确认项已标出，无「假装已确定」

## D. 可编码性

- [ ] 无「稍后细化」却进入编码的关键设计空洞
- [ ] 字段/表/路径足够具体，编码不会自由发挥
