## 5. 核心流程

```
GET /v1/feature-flags/:key
  ├─ 校验 key 非空
  ├─ 鉴权
  ├─ 读缓存，命中则返回
  ├─ 读配置存储
  ├─ 无记录 → enabled=false
  └─ 写缓存并返回 { key, enabled }
```

## 6. 缓存设计

- key 命名与前缀：`feature_flag:{key}`（示例，落地改本仓常量）
- 过期时间：60s
- 并发刷新策略：公共缓存可加锁刷新
- 失效 / 刷新：配置变更时删对应 key
- 数据结构：string / JSON

## 7. 日志与异常

- 关键 log：存储读失败
- 失败策略：读失败返回错误，不把失败伪装成关闭（避免误关）
