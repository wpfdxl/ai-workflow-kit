# 功能开关查询 接口文档

> 虚构样例。顶层包装按目标仓现有约定，这里只写 `data`。

## 1. 文档说明

- 模块：功能开关
- 数据来源：开关配置
- 适用端：App
- 鉴权：登录
- 返回约定：只描述业务字段

## 2. 接口清单

- `GET /v1/feature-flags/:key`：查询单个开关

## 3. 查询功能开关 `GET /v1/feature-flags/:key`

### 3.1 请求

App：

`GET /v1/feature-flags/:key`

参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| key | string | 是 | 路径参数，非空 |

### 3.2 业务规则

- 配置为开 → `enabled` 为 true
- 未配置或为关 → `enabled` 为 false，HTTP 仍成功
- `key` 为空 → 参数错误

### 3.3 返回字段

| 字段 | 类型 | 说明 |
|---|---|---|
| key | string | 查询的开关名 |
| enabled | bool | 是否开启 |

### 3.4 返回示例

#### 正常

```json
{
  "key": "new-home",
  "enabled": true
}
```

#### 空态（未知 key）

```json
{
  "key": "unknown",
  "enabled": false
}
```

#### 错误

```json
{
  "code": 400,
  "message": "key required"
}
```

## 5. 联调建议

- 先测已配置 key，再测未知 key，最后测缺 key。
