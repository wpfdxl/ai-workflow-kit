# 用户资料查询 开发方案

> 阶段：② 示例定稿  
> 依赖：@00_需求.md  
> 规范：@../../profiles/go125-kratos-ddd-sample/RULES.md

## 1. 需求理解

- 一句话目标：按 user_id 只读查询用户资料
- 涉及端：HTTP + gRPC
- 核心数据来源：users 表（示例）

## 2. 影响范围盘点

### 2.1 涉及代码仓 / 服务

- code_root：见 PROJECT.md（示例假定用户服务 `user-service`）
- 服务/模块：user

### 2.2 涉及分层（go125-kratos-ddd-sample）

- api：`api/user/v1/user.proto` — `GetUserProfile`
- biz：`User` 实体、`UserRepo` 接口、`UserUsecase.GetProfile`
- data：`userRepo` 实现（查 DB）
- service：`UserService.GetUserProfile` 转 DTO
- server：注册 User gRPC/HTTP

## 3. 数据模型 / 存储设计

### 3.1 新建表 / 集合 / 资源

- 无（示例假定表已存在）

### 3.2 复用现有

- 表 `users`：`id`、`nickname`、`avatar_url`、`status`、`create_time`、`update_time`

### 3.3 跨库 / 跨服务事务

- [x] 否（只读单库）

## 4. 接口清单

| 序号 | 方法 | 路径 | 鉴权 | 端 | 说明 |
|---|---|---|---|---|---|
| 1 | gRPC | `user.v1.User/GetUserProfile` | 内网/按目标仓 | RPC | 主契约 |
| 2 | GET | `/v1/users/{user_id}/profile` | 同左 | HTTP | proto http 注解 |

## 5. 核心流程

```
GetUserProfile(user_id)
  ├─ user_id <= 0 → InvalidArgument
  ├─ biz.UserUsecase.GetProfile
  │    └─ repo.FindByID → nil → NotFound(USER_NOT_FOUND)
  └─ service 组装 Reply 返回
```

## 6. 缓存设计（如有）

- 一期默认不做
- 若做：data 层 key `user:profile:{id}`，TTL 60s，资料变更时删 key（本期无写接口）

## 7. 日志与异常

- NotFound 打 Info/Debug 即可；DB 错误打 Error
- 对外错误：Kratos errors，reason=`USER_NOT_FOUND`

## 8. 风险与兼容

- 兼容：新增只读接口
- 回滚：下线路由/去掉注册

## 9. 开发任务拆解

- [ ] Task1：proto GetUserProfile + 生成
- [ ] Task2：biz User + UserRepo + GetProfile
- [ ] Task3：data userRepo.FindByID
- [ ] Task4：service 实现 + server 注册
- [ ] Task5：doc json
- [ ] Task6：自检
